CodeSampleX — это **открытая сеть тестирования совместимости** для библиотек, рантаймов и инструментов разработчика. Она не пересказывает документацию и не собирает чужие рассказы: она выполняет реальные сборки и контрактные тесты в реальных, записанных средах — а затем показывает, где всё действительно работало, где ломалось и насколько она уверена и в том, и в другом.

- Карта совместимости: **https://codesamplex.dev**
- Вопрос, на который она отвечает: *запускается ли это там?* — этот API, на этой версии, на этой ОС, под этим рантаймом.
- Ответ, который она даёт: *мы это протестировали; вот что произошло.*

## Запускается ли это там?

Каждый результат — это записанное выполнение с приложенной средой, поэтому данные разворачиваются в матрицы совместимости — ОС × рантайм, версия × архитектура, символ × ОС. Реальный срез из живой сети (`axios.post`, измерено в августе 2026 года):

```text
github.com/jackc/pgx/v5                  v5.10.0     v5.9.2    v5.7.3
whole package                            ✓ 85% 1156  ✓ 100% 2  ✓ —
Batch                                    ✓ 91% 240   —         —
Identifier                                 60% 15    —         ✓ —
```

Эта сетка не иллюстрация, а [живая страница](https://codesamplex.dev/golang/github.com%2Fjackc%2Fpgx%2Fv5).

**Ячейка несёт долю и пометку, но никогда вердикт.** Процент и число рядом — это то, что сделали реальные машины, а галочка значит, что наш образец там работает. Наши запуски — повтор одного контейнера, а тысяча сообщённых — тысяча разных ситуаций, поэтому они не складываются. `✓ —` значит: работающий код есть, но его пока никто не использует. `—` остаётся неизвестным.

## Почему тестирование важно

```text
Documentation   → what should work
Code search     → how somebody used it
Community       → what somebody says worked
CodeSampleX     → what was actually tested
```

Правила, которые сохраняют карту честной:

- Успешная компиляция проекта **никогда** не выдаётся за работоспособность символа. Наблюдения и верификации считаются раздельно и никогда не суммируются.
- Неустановленные причины остаются `UNKNOWN`. Ложный HIT хуже, чем MISS, — `NO_SAFE_MATCH` является полноценным ответом.
- Свидетельства устаревают: вес результата уменьшается вдвое каждые 90 дней, и устаревшие ячейки прямо об этом сообщают.
- Причины сбоев сообщаются как распределения вероятностей, никогда — как выдуманная уверенность.

## Установка CLI

CLI — это локальный тестировщик: он оборачивает ваши реальные сборки, превращает их результаты в анонимные свидетельства и отвечает на вопросы из сети.

Windows (PowerShell):

```powershell
irm https://codesamplex.dev/install.ps1 | iex
```

macOS / Linux:

```bash
curl -fsSL https://codesamplex.dev/install.sh | sh
```

Этой строке нужны `curl` и CA-сертификаты, которых нет в минимальных образах (debian-slim, alpine, большинство контейнеров для агентов), — а `curl … | sh` **завершается с кодом 0, когда curl отсутствует**, потому что конвейер возвращает статус последней команды. Сначала установите зависимости — или используйте wget:

```bash
apt-get install -y curl ca-certificates            # debian / ubuntu slim
apk add --no-cache curl ca-certificates            # alpine
wget -qO- https://codesamplex.dev/install.sh | sh  # needs neither
```

Бинарник попадает в `~/.local/bin`, которого по умолчанию нет ни в чьём `PATH`:

```bash
export PATH="$HOME/.local/bin:$PATH"
csx version    # the install check — `csx --version` is not a spelling csx accepts
```

Один бинарник, один вопрос. `csx init` показывает приведённое ниже соглашение и предлагает единственный выбор — **JOIN COMMUNITY** или **LOCAL ONLY**. При запуске через конвейер в `sh` stdin занят конвейером загрузки, поэтому `init` принимает заявленное значение по умолчанию: JOIN COMMUNITY. Отказаться можно в любой момент командой `csx init --local-only`; оба флага режима можно запускать повторно, и они не интерактивны. Для скриптов и CI: `csx init --community --yes --no-agents`.

## Тестирование и проверка

```bash
csx run -- pnpm build              # wrap any build/test — its result becomes evidence
csx search "axios multipart upload"  # a verified answer, graded for YOUR environment
csx scan                           # record which public packages a project uses, no build
csx stats                          # local dashboard: hits, adoptions, queue
csx ui                             # browser dashboard + privacy preview
csx sync                           # warm the shard cache — once, right after install
```

`csx sync` — не декоративное дополнение: у свежей установки кэш шардов пуст, поэтому каждый поиск возвращает `NO_SAFE_MATCH`, пока не пройдёт синхронизация. Дальше демон сам подогревает кэш в фоне.

`csx search` оценивает каждый результат относительно вашей записанной среды — `EXACT`, `COMPATIBLE`, `ADAPTATION_REQUIRED`, `REFERENCE_ONLY` или `NO_SAFE_MATCH` — и перечисляет точную дельту (`different`, `adaptationNeeded`) между тем, где ответ был доказан, и тем, где находитесь вы.

## Проверенные образцы

Образец — это не сниппет. Это минимальный контентно-адресуемый проект (`sha256:<hex>` его канонического артефакта) с **контрактом**: набором утверждений, которые были выполнены офлайн в закреплённом контейнере и прошли. Цикл создания образцов в «чистой комнате» доступен только через CLI:

```bash
csx sample propose --goal "upload a file with axios"   # sanitized brief, empty workspace
csx sample create <dir>      # ingest the clean-room project
csx sample verify <id>       # resolve → compile → contract, sandboxed
csx sample publish <id>      # requires typing exactly "yes"; leakage findings hard-refuse
```

Перед публикацией выполняется сканирование на секреты, пути, имена проектов и приватные URL — любые находки **блокируют** публикацию, и флага для обхода не существует. Загрузка исходников образца намеренно не является возможностью MCP; опубликовать может только человек за CLI.

## Находки

Где это ломается? [Находки](https://codesamplex.dev/findings) — это список измеренных противоречий: что утверждает документация (или общепринятое мнение) рядом с тем, что измерил контракт, — расхождения с документацией, сбои в конкретных средах, границы версий. Каждая строка ссылается на опубликованный образец, чей контракт это доказывает, так что измерение можно перезапустить и оспорить.

Машинно-выведенные находки вырастают из опубликованных образцов, авторы которых записали опровергаемое ими представление; никто не редактирует страницы, чтобы добавить их вручную.

## Свидетельства и оценка

Почему ячейке можно доверять? Каждый результат несёт свой класс свидетельств, от слабого к сильному:

| Класс | Что произошло на самом деле |
|-------|------------------------|
| `USAGE_OBSERVATION` | реальный проект собрался/прошёл проверку типов/тесты с этим пакетом — наблюдение, слабое свидетельство |
| `ADOPTION_EVIDENCE` | кто-то применил образец и сообщил, прошла ли после этого сборка |
| `SAMPLE_VERIFICATION` | контракт образца выполнился в закреплённом контейнере и прошёл |
| `CROSS_PASS` | независимый пир перезапустил его, и он снова прошёл |
| `MATRIX_PASS` | прошедшие запуски охватывают ≥2 границ ОС/рантайма/браузера |
| `STABLE` | ≥3 независимых пиров проходят его, без единого зафиксированного сбоя за 30 дней |

Страницы образцов также отмечены лестницей верификации `L0_SOURCE_ONLY` → `L5_MATRIX_PASS`, а ячейки матриц несут уровень уверенности (`HIGH`/`MEDIUM`/`LOW`), флаги повышенной частоты сбоев и даты последнего наблюдения. Только подписанные **квитанции v2** могут заявлять `resolvedPackages` — версии, которые верификатор действительно установил, а не версии, которые набрал автор; снимки относят каждую квитанцию к той версии, которая реально выполнялась.

Публичные счётчики — это сводка, доступная как JSON без учётной записи:

```bash
curl -fsSL https://codesamplex.dev/v1/stats
```

| Поле | Что оно считает |
|-------|----------------|
| `packages` / `symbols` | покрытие: имена публичных пакетов и наблюдавшиеся символы в данных о совместимости |
| `evidence` | принятые записи наблюдений; не пользователи, не проекты и не проверенные образцы |
| `verifiedSamples` | уникальные образцы с квитанцией contract-PASS из песочницы |
| `peers` / `projectsMonth` | уникальные анонимные дневные/месячные корзины участников |
| `postHitBuildsReported` | отчёты о применении, содержавшие измеренный PASS или FAIL |

CodeSampleX **пока не измеряет надёжно уникальных/активных пользователей, работающие MCP-процессы или успешные установки**. Любое поле `estimated*` в ответе статистики рассчитано по явной формуле и не должно читаться как измеренное значение.

## Воркер участника

Среды сети — это машины других людей. Свободная машина может участвовать в Docker-изолированной верификации, не трогая конфигурацию MCP или агентов:

```bash
csx init --community --yes --no-agents --no-daemon
csx worker start                         # idle-aware, 2 Docker lanes
csx worker start --parallel 4 --budget 15m
```

Воркер принимает только назначенные сервером задания VERIFY (`cross` / `matrix`) — очередь никогда не присылает произвольную shell-команду. Артефакты контентно-адресуемы и проверяются по хэшу; resolve выполняется в контейнере; стадии компиляции и контракта работают с отключённой сетью в одноразовых Docker-пространствах с фиксированными лимитами памяти `512m` и числа PID `256`; отсутствие демона Docker — жёсткий отказ, а не откат на хост. Результаты — квитанции v2, подписанные ed25519; сырые логи стадий остаются локально. См.

## Агентный адаптер (MCP)

Кодовые агенты пользуются той же сетью через адаптер — MCP является коннектором поверх CLI и API, а не продуктом:

```text
CodeSampleX
├─ CLI   ← primary local tester
├─ API   ← automation / integration
├─ Web   ← compatibility map / reports
└─ MCP   ← agent adapter
```

`csx init` настраивает Claude Code, Codex, Gemini CLI и OpenCode автоматически. Любой другой stdio-MCP-клиент (Cursor, Windsurf, Cline, Zed, VS Code) работает по тому, что печатает `csx mcp-config` (`--toml` для Codex), — команда выводит абсолютный путь к бинарнику, который необходим клиенту, запускаемому редактором. Сам сервер — это `csx mcp`. Восемь инструментов: `search_known_solution`, `get_sample`, `explain_compatibility`, `run_observed_command`, `report_sample_adoption`, `propose_public_sample`, `list_local_hits`, `get_local_stats` — и намеренно ни одного инструмента публикации.

Шаги установки, рассчитанные на агентов (включая MCPB-бандл и прямую загрузку бинарников с `SHA256SUMS.txt`): [llms-install.md](../../llms-install.md). Автономные community-установки автообновляются по манифесту, подписанному Ed25519, с доступной командой `csx update rollback`; установки local-only не делают запросов на обновление.

## Соглашение

```text
You get                              You contribute
✓ Public compatibility knowledge     ✓ Public package/version usage
✓ Verified code answers              ✓ Public API/symbol usage when detectable
✓ Local agent integration            ✓ Build/typecheck/test result
✓ Public sample cache                ✓ Sanitized failure fingerprints

Never shared automatically
✕ Source code        ✕ Repository/project name   ✕ File names or paths
✕ Source snippets    ✕ Secrets or env variables  ✕ Private packages
✕ Raw compiler/runtime logs
```

Это не скрытая телеметрия — это сам протокол. Участники сообщества являются одновременно потребителями **и** производителями. Режим local-only никогда ничего не отправляет. Ошибки санируются локально в отпечатки до любого использования; приватные и неизвестные пакеты никогда не покидают машину; предпросмотр приватности в `csx ui` показывает точное содержимое данных до их отправки. `NO_SAFE_MATCH` вносит безопасный для приватности кортеж Wanted — публичный пакет, его точную версию и, если запрос назвал один однозначный пакет, запрошенные публичные символы, — и никогда не промпт пользователя. Публичное развёртывание принимает исходники образцов **только от сидеров**; поиск, свидетельства, квитанции и доска wanted открыты без учётной записи.

## Экосистемы (Public v1)

**Сканирование и верификация** — проекты обнаруживаются, пакеты разрешаются по lockfile, образцы верифицируются от начала до конца: Node/TypeScript (npm, pnpm, yarn — эталон), Python (pip, uv), Go, Rust/Cargo. Образцы Node выполняются на том рантайме, который они объявляют, поэтому результаты для Bun и Deno реальны, а не предположены.

**Только верификация** — сканера проектов пока нет, но опубликованные образцы собираются и проходят контрактные тесты в закреплённом контейнере: PHP/Composer, Ruby/Bundler, Dart/pub, Elixir/Hex. Контрактная верификация Java (Maven/Gradle) закрепляет точные линии JDK 8/11/17/21/25.

Честная матрица возможностей: [docs/adapters.md](../adapters.md) — уверенность разрешения символов всегда помечена явно (`EXACT`/`PROBABLE`/`UNKNOWN`).

## Архитектура

Один бинарник на Go (`csx`: демон + CLI + MCP + пиринговый узел + верификатор) и небольшой сервер (`csx-server`: PostgreSQL + обозреватель совместимости с серверным рендерингом за Caddy). Образцы контентно-адресуемы и распространяются по схеме «сначала локальный кэш → пиры → главный сидер». Скачанные образцы никогда не выполняются напрямую на хосте: разрешение зависимостей идёт в закреплённой песочнице с отключёнными install-скриптами там, где экосистема это поддерживает, после resolve артефакт хэшируется заново, а стадии компиляции и контракта выполняются с отключённой сетью. См. [goal.md](../../goal.md), [docs/execution-context.md](../execution-context.md), [docs/operations.md](../operations.md).
